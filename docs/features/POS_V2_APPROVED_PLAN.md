# SERVIX POS V2 — الاعتمادات والمتطلبات المعتمدة

> **التاريخ:** 26 أبريل 2026
> **المعتمد:** صاحب المشروع
> **الحالة:** معتمد للتنفيذ
> **المرجع:** جلسة المراجعة التقنية 26/04/2026

---

## الوضع الحالي

الكاشير الحالي يتكون من 13 ملف (~2500 سطر) ويدعم:
- عرض الخدمات بالتصنيفات + بحث + مفضلات
- سلة مشتريات مع كميات وخصم لكل خدمة
- اختيار عميل (بحث أو walk-in)
- اختيار موظفة افتراضية + تغيير لكل خدمة
- دفع (نقدي / بطاقة / تحويل / Apple Pay / مقسّم)
- تعليق واستدعاء فواتير
- إرجاع أساسي (رقم فاتورة + سبب)
- إرسال فاتورة واتساب / إيميل
- QR للفاتورة العامة
- كوبونات خصم
- حساب عمولات الموظفات
- تحضير/حضور الموظفات
- كود الطلب الذاتي (Self-Order)
- وضع Desktop + Touch (تكيّف تلقائي)

## A. إصلاحات حرجة (أولوية قصوى)

### A1. درج نقدي (Cash Drawer)
**الحالة:** غير موجود بالكامل
**المطلوب:**

| الميزة | التفصيل |
|--------|---------|
| فتح وردية | `POST /pos/shifts/open` — إدخال مبلغ البداية (float) |
| إغلاق وردية | `POST /pos/shifts/close` — إدخال المبلغ الفعلي في الصندوق |
| عداد نقدي مباشر | يعرض "النقد المتوقع" بناء على: مبلغ البداية + مبيعات نقد - إرجاعات - مصروفات |
| سحب نقد | تسجيل سحب من الصندوق (مثل: المالكة أخذت مبلغ) |
| تسجيل مصروف | مصروفات سريعة من الصندوق (قهوة، مستلزمات، صيانة) — مع تصنيفات |
| فرق الصندوق | عند الإغلاق: المتوقع vs الفعلي = عجز/فائض |

**ملاحظة:** الكاشيرة لا تستطيع إصدار فواتير قبل فتح الوردية.

---

### A2. حماية الخصومات
**الحالة:** خصم مفتوح بلا حد — أي كاشيرة تخصم أي مبلغ
**المطلوب:**

| القاعدة | التفصيل |
|---------|---------|
| سقف حسب الدور | كاشيرة: max 10% — مديرة: max 50% — مالكة: مفتوح |
| موافقة PIN | خصم أعلى من السقف → يطلب PIN المديرة/المالكة |
| سبب الخصم | حقل إلزامي عند أي خصم |
| تسجيل | كل خصم يُسجل: مين أعطاه + كم + ليش + متى |
| تقرير يومي | "الخصومات الممنوحة" ضمن تقرير الوردية |

---

### A3. تقرير الوردية (Z-Report)
**الحالة:** غير موجود
**المطلوب:** يظهر عند إغلاق الوردية ويشمل:

- عدد الفواتير
- المبيعات حسب طريقة الدفع (نقدي / بطاقة / تحويل / Apple Pay)
- الخصومات الممنوحة (إجمالي + تفصيل)
- الإرجاعات
- المصروفات من الصندوق
- النقد المتوقع vs الفعلي (عجز/فائض)
- أعلى خدمة مبيعاً
- أعلى موظفة أداءً
- **قابل للطباعة أو الإرسال عبر واتساب للمالكة**

---

### A4. العميل الوهمي — إلغاء إنشاء عملاء بأرقام عشوائية
**الحالة:** كل فاتورة بدون عميل = عميل جديد وهمي برقم عشوائي → يلوث قاعدة البيانات
**المطلوب:** 3 خيارات واضحة:

| الخيار | التفصيل |
|--------|---------|
| 👤 زائر بدون تسجيل | عميل واحد ثابت لكل صالون اسمه "زائر" — يُنشأ مرة واحدة عند إعداد الصالون |
| ✏️ اسم بدون رقم | العميلة تعطي اسمها بس بدون رقم جوال (اختياري) |
| 📋 تسجيل كامل | اسم + رقم → عميل حقيقي → نقاط ولاء + تاريخ زيارات |

**القاعدة:** لا يتم إنشاء عميل جديد برقم عشوائي أبداً.

## B. إصلاحات حفظ البيانات

### B1. الفواتير المعلقة — حفظ عند Refresh
**الحالة:** الفواتير المعلقة في `useState` فقط — تضيع عند تحديث الصفحة
**الحل:** `localStorage` كحل فوري، ثم حفظ في API مستقبلاً

### B2. المفضلات — حفظ عند Refresh
**الحالة:** نفس المشكلة — المفضلات ترجع للـ default عند كل تحديث
**الحل:** `localStorage`

### B3. إعدادات الإيصال — حفظ فعلي
**الحالة:** زر "حفظ" يعرض toast "تم الحفظ" لكن لا يحفظ شيء فعلياً
**الحل:** حفظ في Settings الصالون عبر الـ API

## C. تحسينات الوظائف

### C1. نظام الإرجاع المتقدم
**الحالة:** إدخال رقم الفاتورة يدوياً + سبب فقط
**المطلوب:**

- بحث عن الفاتورة → عرض تفاصيلها (الخدمات + المبالغ + طريقة الدفع)
- إرجاع جزئي — اختيار خدمات محددة من الفاتورة
- حساب المبلغ المسترد تلقائياً
- تحديد طريقة الإرجاع (نقد / يرجع على البطاقة)
- طباعة إشعار إرجاع

### C2. ربط نقاط الولاء
**الحالة:** `loyalty` module موجود في الـ API لكن الكاشير لا يستفيد منه
**المطلوب:**

- لما تختار العميلة → يظهر رصيد نقاطها
- زر "استبدال نقاط" → يخصم من الإجمالي
- إضافة نقاط تلقائياً بعد إصدار الفاتورة

### C3. حساب الضريبة من الإعدادات
**الحالة:** `TAX = 0.15` ثابتة في الكود
**المطلوب:**

- تجي من `salonInfo.taxPercentage` (موجودة فعلاً في API سطر 115)
- الكاشير يقرأها من الإعدادات بدل الثابت

**ملاحظة:** الـ API يقرأ `taxPercentage` من `salonInfo` بالفعل. الكاشير (Frontend) هو اللي ثابت 15%.

### C4. حساب الباقي (Change Calculator)
**الحالة:** غير موجود
**المطلوب في الدفع النقدي:**

- حقل "المبلغ المستلم"
- حساب تلقائي "الباقي"
- أزرار سريعة: `500` `200` `100` `50` `المبلغ بالضبط`

## D. ميزات جديدة — مواعيد اليوم

### D1. تاب "المواعيد" في الكاشير (Today's Queue)
**المطلوب:** تاب جديد بجانب الخدمات/المفضلات/الباقات يعرض مواعيد اليوم:

| الحالة | اللون | المعنى |
|--------|-------|--------|
| 🟢 | أخضر | العميلة وصلت (checked-in) |
| 🟡 | أصفر | الموعد قادم |
| ⬜ | رمادي فاتح | لم تصل بعد |
| ✅ | رمادي | اكتملت وصدرت فاتورة |
| 🔴 | أحمر | متأخرة 15+ دقيقة |
| ❌ | شطب | ألغت |

**كل موعد يعرض:**
- اسم العميلة + رقمها
- الخدمات المحجوزة
- الموظفة المحددة
- السعر المتوقع
- ملاحظات العميلة (حساسية مثلاً)
- رصيد نقاط الولاء
- تنبيه لو عليها دين سابق

### D2. تحويل الموعد للسلة بضغطة واحدة
**المطلوب:** زر "تحويل للسلة" على كل موعد:

1. تحميل بيانات العميلة تلقائياً
2. إضافة كل خدمات الموعد للسلة مع الموظفة المحددة
3. ربط الفاتورة بالموعد (`appointmentId`)
4. بعد إصدار الفاتورة → حالة الموعد تتحدث لـ "مكتمل"

**ملاحظة:** الكاشيرة تقدر تضيف خدمات إضافية يدوياً فوق اللي جاء من الموعد.

### D3. إدخال مصروف سريع (Quick Expense)
**المطلوب:** زر في الهيدر → modal:

- المبلغ
- الفئة: مستلزمات / مشروبات / صيانة / أخرى
- ملاحظة
- من الصندوق: نعم/لا
- ينخصم من "النقد المتوقع" ويظهر في تقرير الوردية

## E. نظام تسليم الفاتورة — 6 قنوات

### E1. القنوات الجاهزة (4)

| القناة | الحالة | التفصيل |
|--------|--------|---------|
| 📲 واتساب | ✅ جاهز | يرسل PDF عبر WhatsApp Business API |
| 📧 إيميل | ✅ جاهز | يرسل PDF كمرفق |
| 💬 SMS | ✅ جاهز | نص فقط (رقم الفاتورة + المبلغ) |
| 📱 QR | ✅ جاهز | `publicToken` يتولد تلقائي + modal في الكاشير |

### E2. القنوات الجديدة المعتمدة (2)

#### 📳 NFC — نظام الطابور الذكي

**المبدأ:** ملصق NFC على طاولة الكاشير (3 ريال). العميلة تحط جوالها → تظهر فاتورتها.

**التدفق التقني:**
1. الكاشيرة تصدر الفاتورة → تدخل طابور الـ terminal
2. العميلة تلمس NFC → endpoint يأخذ أقدم فاتورة غير مُستلمة → يشطبها atomically
3. يوجّه لصفحة الفاتورة العامة

**Endpoint:**
```
GET /public/tap/:salonSlug/:terminalId
```

**المنطق:**
```sql
UPDATE invoices
SET nfc_claimed_at = NOW()
WHERE id = (
  SELECT id FROM invoices
  WHERE terminal_id = :terminalId
    AND nfc_claimed_at IS NULL
    AND created_at > NOW() - INTERVAL '30 minutes'
  ORDER BY created_at ASC
  LIMIT 1
  FOR UPDATE SKIP LOCKED
)
RETURNING id, public_token
```

**الحماية:**
- قفل زمني: 3 دقائق فقط بعد الإصدار
- لمسة واحدة فقط (atomic claim)
- `FOR UPDATE SKIP LOCKED` يمنع تسليم نفس الفاتورة لشخصين

**تحكم الكاشيرة — شريط الفواتير:**
بدال أزرار "التالي/الماضي"، شريط مرئي يعرض كل الفواتير الأخيرة كبطاقات:

| البطاقة | اللون | الحالة |
|---------|-------|--------|
| 🟢 نشطة | أخضر متوهج | بانتظار لمسة العميلة + مؤقت عد تنازلي |
| 🟡 جاهزة | أصفر خافت | زر "فعّلي" — الكاشيرة تضغط لتفعيل |
| ✅ تم | رمادي | تم الاستلام |

**سيناريوهات التحكم:**
- العميلة تأخرت → الكاشيرة تضغط على فاتورة العميلة التالية لتفعيلها
- العميلة رجعت → الكاشيرة تضغط على فاتورتها لإعادة تفعيلها
- العميلة شبكتها طافية → 3 خيارات بديلة:
  1. 📤 أرسلي واتساب
  2. 🖨️ اطبعي إيصال
  3. 📱 اعرضي QR

**الحقول الجديدة في DB:**
- `nfc_claimed_at` (DateTime, nullable) على جدول الفواتير
- `terminal_id` (String, nullable) على جدول الفواتير

**الهاردوير:** ملصق NFC واحد بـ 3 ريال لكل كاونتر — يشتغل على iPhone 7+ وكل أجهزة Android

#### 🖨️ طباعة الإيصال

**الحالة:** زر موجود بدون `onClick`
**المطلوب:**
- تنسيق إيصال حراري (عرض 80mm)
- `window.print()` مع CSS `@media print`
- يشمل: شعار الصالون + رقم الفاتورة + الخدمات + الضريبة + الإجمالي + QR

## F. تحسينات الواجهة (UI/UX)

### F1. تكبير الأرقام والنصوص
**الحالة:** أسعار `13px`، أيقونات `8-9px` — صغيرة جداً لكاشيرة واقفة
**المطلوب:**

| العنصر | الحالي | المطلوب |
|--------|--------|---------|
| اسم الخدمة | `text-[11px]` | `text-[14px]` minimum |
| سعر الخدمة | `text-[13px]` | `text-[16px]` minimum |
| الإجمالي | `text-[17px]` | `text-[24px]` |
| أزرار الدفع | صغيرة | أكبر بـ 30% |
| اسم الموظفة | `text-[7px]` | `text-[10px]` minimum |

### F2. أصوات التفاعل (Audio Feedback)
**المطلوب:**
- `beep` خفيف عند إضافة خدمة للسلة
- `cha-ching` عند إصدار فاتورة ناجحة
- `error buzzer` عند خطأ
- Web Audio API — خفيف بدون ملفات صوتية خارجية

### F3. شريط الأداء المباشر في الهيدر
**المطلوب:** شريط صغير يعرض:
```
مبيعات اليوم: 4,350 ر.س | فواتير: 12 | متوسط: 362 ر.س
```

### F4. تسلسل الفواتير
**المطلوب:** عرض في الهيدر:
- رقم آخر فاتورة
- عدد فواتير اليوم

### F5. "تكرار آخر فاتورة"
**المطلوب:** لما تختار عميلة → زر "تكرار آخر زيارة" يجلب نفس الخدمات من آخر فاتورة لها.
